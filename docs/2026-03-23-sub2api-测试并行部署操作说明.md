# 2026-03-23 sub2api 测试并行部署操作说明

## 目标

在同一台服务器上同时运行：

- 正式服务：继续使用正式数据库 `sub2api`
- 测试服务：使用从正式库克隆出的测试数据库 `sub2api_test`

避免测试代码直接读写正式库，降低误操作风险。

## 当前实际端口

- 正式服务：`127.0.0.1:8080`
- 测试服务：`0.0.0.0:8081`

健康检查：

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8081/health
```

## 当前目录约定

- 正式部署目录：`/root/sub2api/deploy`
- 当前测试代码目录：`/root/flyingcys/sub2ap-session-turn`
- 测试 compose：`/root/flyingcys/sub2ap-session-turn/deploy/docker-compose.reuse-stack-test.yml`

## 原则

1. 不让测试服务直接连接正式库 `sub2api`
2. 每次准备测试前，先备份正式库
3. 用正式库备份恢复出 `sub2api_test`
4. 测试服务只连接 `sub2api_test`

## 一次完整流程

### 1. 确认正式服务正常

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
curl http://127.0.0.1:8080/health
```

### 2. 停掉测试服务

```bash
cd /root/flyingcys/sub2ap-session-turn/deploy
docker compose -f docker-compose.reuse-stack-test.yml stop
```

### 3. 备份正式库

```bash
mkdir -p /root/sub2api/deploy/db_backups
TS=$(date -u +%Y%m%dT%H%M%SZ)
BACKUP=/root/sub2api/deploy/db_backups/sub2api_${TS}.dump

docker exec sub2api-postgres \
  pg_dump -U sub2api -d sub2api -Fc -f /tmp/sub2api.dump

docker cp sub2api-postgres:/tmp/sub2api.dump "$BACKUP"
docker exec sub2api-postgres rm -f /tmp/sub2api.dump

echo "$BACKUP"
```

### 4. 重建测试库

```bash
docker exec sub2api-postgres \
  psql -U sub2api -d postgres -v ON_ERROR_STOP=1 \
  -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = 'sub2api_test' AND pid <> pg_backend_pid();" \
  -c "DROP DATABASE IF EXISTS sub2api_test;" \
  -c "CREATE DATABASE sub2api_test OWNER sub2api;"
```

### 5. 用正式库备份恢复测试库

把上一步生成的备份路径替换到下面命令里：

```bash
docker cp /root/sub2api/deploy/db_backups/sub2api_YYYYMMDDTHHMMSSZ.dump \
  sub2api-postgres:/tmp/sub2api_test.dump

docker exec sub2api-postgres \
  pg_restore -U sub2api -d sub2api_test --clean --if-exists /tmp/sub2api_test.dump

docker exec sub2api-postgres rm -f /tmp/sub2api_test.dump
```

### 6. 确认测试服务连接的是测试库

测试专用环境文件是 `deploy/.env.test`，其中应为：

```env
DATABASE_DBNAME=sub2api_test
```

不要把它改回 `sub2api`。

### 7. 启动测试服务

```bash
cd /root/flyingcys/sub2ap-session-turn/deploy
docker compose -f docker-compose.reuse-stack-test.yml up -d
```

首次本地源码构建会比较慢。若镜像已构建过，后续 `up -d` 会很快。

### 8. 验证正式和测试是否分离

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8081/health

docker exec sub2api-postgres psql -U sub2api -d sub2api -Atc \
  "select count(*) from accounts;"

docker exec sub2api-postgres psql -U sub2api -d sub2api_test -Atc \
  "select count(*) from accounts;"
```

## 风险提示

- 不要让测试服务连接正式库 `sub2api`
- 不要在 `/root/sub2api/deploy` 下随手执行默认的 `docker compose up -d`
- 正式目录应显式使用 `docker-compose.local.yml`
- 如果要重建正式服务，建议使用：

```bash
cd /root/sub2api/deploy
docker compose -f docker-compose.local.yml up -d
```
