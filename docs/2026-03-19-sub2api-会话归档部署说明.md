# sub2api 会话归档部署说明

## 状态说明

当前仓库的会话归档已经改为 **直接内置在 `sub2api` 服务中**。

也就是说，当前正式链路不再是：

```text
Nginx -> Python archive_proxy -> sub2api
```

而是：

```text
客户端 -> sub2api（内置会话归档补丁）
```

旧的外置 Python 代理方案仅保留为历史讨论，不再作为当前部署方式。

## 归档范围

当前版本会在以下入口归档客户端视角的原始 request / response：

- `POST /v1/messages`
- `POST /v1/responses`
- `POST /v1/responses/*subpath`（例如 `/v1/responses/compact`）
- `POST /responses`
- `POST /responses/*subpath`（例如 `/responses/compact`）
- `POST /v1/chat/completions`
- `POST /chat/completions`

当前首版边界如下：

- 只保存客户端发给 `sub2api` 的请求，以及客户端最终收到的响应
- 不保存 `sub2api -> 上游模型` 的内部转发流量
- WebSocket 只保证主链路兼容，不做帧级归档

## 落盘结构

归档目录按 `session -> turn` 组织：

```text
data/archive/conversations/
  sess_<stable-hash>/
    0001.json
    0002.json
    0003.json
```

每个 `000N.json` 都是一个结构化 JSON 文档，同时包含：

- 原始 HTTP request
- 最终 HTTP response
- `session_dir` 与 `turn` 元数据

目录名不会直接暴露原始 `session_id` / `conversation_id`，而是稳定哈希后的 `sess_<hash>`。

## 默认路径

当前默认归档根目录为：

```text
data/archive/conversations
```

不同部署方式下的实际落盘位置如下：

- Docker / Docker Compose：`/app/data/archive/conversations`
- 二进制 + systemd：`/opt/sub2api/data/archive/conversations`
- 本地源码运行：`<项目工作目录>/data/archive/conversations`

如需覆盖默认值，可设置环境变量：

```text
SUB2API_CONVERSATION_ARCHIVE_ROOT
```

## Docker 部署

仓库内的以下模板已经显式配置归档目录：

- `deploy/docker-compose.yml`
- `deploy/docker-compose.local.yml`
- `deploy/docker-compose.dev.yml`

默认值统一为：

```text
/app/data/archive/conversations
```

因此只要保留 `/app/data` 的卷挂载，归档文件就会跟随容器数据一起持久化。

如果你使用自定义 Compose 文件，请至少保证两件事：

1. 挂载 `/app/data`
2. 设置：

```yaml
environment:
  SUB2API_CONVERSATION_ARCHIVE_ROOT: /app/data/archive/conversations
```

## 二进制 + systemd 部署

仓库内的以下模板已经显式配置归档目录：

- `deploy/sub2api.service`
- `deploy/install.sh` 生成的 `sub2api.service`

默认值统一为：

```text
/opt/sub2api/data/archive/conversations
```

如果你使用自定义 systemd 单元，请在 `[Service]` 中补上：

```ini
Environment=SUB2API_CONVERSATION_ARCHIVE_ROOT=/opt/sub2api/data/archive/conversations
```

## 验证方法

### Docker

发起一次 `Codex` 或 `Claude Code` 对话后，优先直接在容器内检查：

```bash
docker compose -f deploy/docker-compose.yml exec sub2api \
  find /app/data/archive/conversations -type f | sort
```

预期至少能看到：

- `sess_<hash>/0001.json`

如需检查内容：

```bash
docker compose -f deploy/docker-compose.yml exec sub2api \
  sed -n '1,120p' /app/data/archive/conversations/sess_<hash>/0001.json
```

补充说明：

- `deploy/docker-compose.yml` 默认使用命名卷 `sub2api_data`，因此不应默认去查宿主机 `deploy/data/...`
- `deploy/docker-compose.local.yml` 和 `deploy/docker-compose.dev.yml` 使用宿主机 bind mount 时，也可以直接检查：

```bash
find deploy/data/archive/conversations -type f | sort
```

### 二进制 + systemd

发起一次对话后检查：

```bash
find /opt/sub2api/data/archive/conversations -type f | sort
```

预期至少能看到：

- `sess_<hash>/0001.json`

## 运维注意事项

- 当前补丁没有单独的运行时开关
- 如果只是想调整位置，请改 `SUB2API_CONVERSATION_ARCHIVE_ROOT`
- 如果要彻底停用归档，需要回退到未包含该补丁的二进制或镜像
- 归档内容可能包含 prompt、代码片段、工具参数和文件路径，必须按敏感数据管理
