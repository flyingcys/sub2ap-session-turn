# sub2api 对话归档实施说明

> 已废弃（2026-03-19）。
> 当前仓库不再使用外置 Python `archive_proxy`、独立 `systemd` 服务或 Nginx 二级代理链路。
> 请改看 `docs/2026-03-19-sub2api-会话归档部署说明.md`。

## 实施目标

在不修改 `sub2api` 源码的前提下，通过新增一个本机 `Python` 归档代理，保存 `Codex` 和 `Claude Code` 的真实对话请求与响应。

## 当前链路

- `/v2ray -> 127.0.0.1:10000`
- `/ -> 127.0.0.1:8080`

## 调整后链路

- `/v2ray -> 127.0.0.1:10000`
- `/ -> 127.0.0.1:18080 -> 127.0.0.1:8080`

## 归档范围

### 归档

- `POST /v1/messages`
- `POST /v1/responses`
- `POST /responses`
- `POST /chat/completions`

### 跳过

- `POST /api/event_logging/batch`
- `POST /v1/messages/count_tokens`
- 页面、静态资源、后台接口
- `/v2ray`

## 部署步骤

### 1. 准备目录

```bash
mkdir -p /opt/sub2api-archive-proxy
mkdir -p /var/log/sub2api-archive
mkdir -p /etc/sub2api
```

### 2. 拷贝代码

把以下目录内容部署到目标机：

```text
sub2api/tools/archive_proxy/
```

### 3. 安装依赖

```bash
cd /opt/sub2api-archive-proxy
python3 -m pip install -e ".[dev]"
```

### 3.1 准备 token 映射文件

如需把 token 前缀映射成更可读的名称，可创建：

```text
/etc/sub2api/archive-token-map.json
```

示例内容参考 [sub2api-archive-token-map.example.json](/home/share/samba/ai-coding/sub2api/deploy/sub2api-archive-token-map.example.json)。

### 3.2 可选：调整归档大小上限

当前默认值：

- 请求体归档上限：`1048576`
- 响应体归档上限：`8388608`
- 仅归档命中 token 映射文件的请求：`true`

如需调整，可修改 `systemd` 环境变量：

- `ARCHIVE_PROXY_ARCHIVE_REQUEST_MAX_BYTES`
- `ARCHIVE_PROXY_ARCHIVE_RESPONSE_MAX_BYTES`
- `ARCHIVE_PROXY_REQUIRE_TOKEN_MAP_MATCH`

### 4. 本地验证

```bash
cd /opt/sub2api-archive-proxy
pytest -q
python3 -m archive_proxy
```

预期：

- 监听 `127.0.0.1:18080`

### 5. 配置 systemd

把 [sub2api-archive-proxy.service](/home/share/samba/ai-coding/sub2api/deploy/sub2api-archive-proxy.service) 拷贝到：

```text
/etc/systemd/system/sub2api-archive-proxy.service
```

然后执行：

```bash
systemctl daemon-reload
systemctl enable --now sub2api-archive-proxy
systemctl status sub2api-archive-proxy
```

### 6. 修改 Nginx

参考 [nginx-sub2api-archive-proxy.conf.example](/home/share/samba/ai-coding/sub2api/deploy/nginx-sub2api-archive-proxy.conf.example)：

- 保持 `location /v2ray` 不变
- 把 `location /` 的 `proxy_pass` 改到 `127.0.0.1:18080`

改完后：

```bash
nginx -t
systemctl reload nginx
```

## 验证方法

### Claude Code

发起一次正常对话后，检查：

```bash
find /var/log/sub2api-archive -type f | sort
```

预期能看到：

- `meta.json`
- `request.bin.gz`
- `response.bin.gz`

此外归档目录会自动：

- gzip 压缩
- 清理超过保留天数的旧日期目录
- 对超限请求/响应只保留上限内内容，并在 `meta.json` 标记 `*_truncated=true`

### Codex

发起一次 `responses` 对话后，检查同样目录。

## 回滚方案

如果代理异常：

1. 把 `Nginx` 的 `location /` 改回 `127.0.0.1:8080`
2. 执行：

```bash
nginx -t
systemctl reload nginx
systemctl stop sub2api-archive-proxy
```

这样就能恢复到当前架构，不影响 `v2ray`。
